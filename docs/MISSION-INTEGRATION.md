Task 11 adds optional strict v3 run fields. Old records remain readable; absent history cannot certify authorship. Back up authority before upgrading. `integrations` is a maximum 32-entry history. Each record binds id, assignmentId, workspaceId, workerBase, workerHead, workerFingerprint, commits (1–256 literal object IDs), changedPaths (maximum 5000), before source, time and state (pending/completed/conflict/unknown). Optional after source, resultingCommits, error and command {id,state:pending/running/completed/unknown} retain the outcome. Intent is durable before the single cherry-pick command. Worker snapshots must be clean, exactly at the assignment base/head, linear, and restricted to owned paths. Both rename endpoints, deletions and all intermediate commit paths are inspected; policy segments .git/.agents/.codex are forbidden case-insensitively. Rejected bytes remain in the worker. Conflict bytes and both heads remain in the integration worktree and receipt. No reset, ours/theirs preference, retry or automatic cleanup occurs.

`authorHistory` is a maximum 256-entry append-only history of {id,taskId,provider,time,state:pending/ready/unknown,threadId?}. Main persists the pending entry before session creation and the ready thread identity before any writing turn. Missing or unresolved history, old unobserved sessions, extra commits and ambiguous session identity fail closed. History is independent of invalidatable verification. Base source is the captain-approved starting snapshot; all subsequent integration commits require this history and retained integration receipts.

`combinedChecks` is a maximum 1000-entry history of {id,workspaceId,source,criterionIds,kind,state:pending/completed/unknown,time,result?}. Result stores the actual bounded MissionEvidence execution receipt, including before/after fingerprints and exit status. `repairProofs` (maximum 256) binds {id,findingId,reviewId,checkId,source,time}; only a trusted main verifier may install a finding-specific passing regression receipt. A generic script or model assertion does not prove arbitrary criteria or fixes. The main-only verification API accepts a trusted coverage adapter; there is no provider/renderer installer. Missing coverage, missing selected result/artifacts, unsupported playable proof and incomplete history remain blocked.

One physical and logical integration reservation is held through effect and durable receipt. Recovery reconstructs pending/unknown/conflict reservations independent of task status. A lost command response or failed receipt keeps the operation unknown and reserved; no automatic reconciliation or retry. The shared Task 12 stop path can inspect `Hub.integrationCommands()` and use the exposed owned command controller. It must persist its shared stop intent first. Cancellation never proves Git did not run and cannot release unknown reservations.

Hub main APIs: `inspectWorkerResult({runId,assignmentId,head})`, `integrateWorkerResult({runId,assignmentId,head,expectedRevision,expectedSource})`, and `verifyCombinedSource({runId,expectedRevision,missionId}, trustedCoverage)`. The lower service exports `inspectWorkerResult({assignment,workspace,head})` and `integrateCandidate({run,workspace,candidate,expectedSource})` through a Hub-bound MissionIntegration. Main revalidates IDs, original criteria, workspace and exact source before and after every authority barrier. Verification re-executes checks in the actual integration tree, hashes guarded artifacts, binds the selected result, and queues an unused independent reviewer at that exact checkpoint via Task 10 scheduling. Existing reviews and receipts remain historical. New integration deletes current verification/readiness. Live supervision/tool containment stays disabled. These contracts are proved only with explicitly offline disposable repositories and providers. External editors remain outside process locks, so drift at every inspected boundary rejects. `integrationCommands()` includes both active integration commands and combined checks. Controllers have id/reservationId/runId/workspaceId/kind/state/exited, an observed pid while running, and cancel() when a process is owned. A cancellation request is distinct from process close. Check cancellation uses the existing checked process-tree cleanup path; Git cancellation requests a process signal and its outcome remains unknown. Recovered controllers expose no invented PID or cancel function and keep exited=false. Task 12 must use its shared durable stop/reconciliation policy; no second run-control dispatcher is introduced.

Coverage adapters are main-owned functions, unavailable through IPC or provider tools: `coverage({kind,result,source,criteria,root})` returns criterion IDs established by that actual execution; `repairCoverage({kind,result,source,findings,root})` returns findings established by a specific passing regression or direct artifact inspection. No default mapping promotes a generic npm success to criterion proof. Missing adapters yield retained execution receipts but no criterion certification. Playable checks are unsupported here and remain missing until the downstream playable verifier exists. This is intentionally narrower than claiming arbitrary criterion understanding.
