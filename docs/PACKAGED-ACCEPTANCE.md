# Contained offline packaged acceptance

2026-10-05. This is a private verification harness, not a production process executor. Product provider admission, fixture manifest/nonce/ACL and package validation remain independent. Source contracts and fake-adapter tests alone do not establish that native containment or the packaged application works on this host. A reviewed contained startup pilot is required before broader native verification.

Use the Node 24 supervisor with canonical absolute paths to a candidate package and two empty, isolated sibling profile/output directories:

```powershell
& 'C:/Program Files/nodejs/node.exe' scripts/packaged-supervisor.cjs '--exe=C:/private/candidate/Sunny HQ.exe' '--asar=C:/private/candidate/resources/app.asar' '--profile=C:/private/run/profile' '--out=C:/private/run/output' --scenario=startup --mib=1 --timeout-ms=120000
```

The legacy inner PowerShell driver now refuses an ordinary direct invocation. Its private `ContainedJob` switch and current-process job check are defense in depth, not independent proof of the specific supervisor job. Only a successful outer receipt establishes this harness's complete containment/identity chain. Do not invoke the inner driver manually or supply the private switch to bypass the supervisor.

`timeout-ms` is an explicit **whole-run** deadline, including worker setup, runtime compilation, application launch, every restart phase, observations and result verification. It is no longer a per-phase allowance. The supervisor arms its clock before requesting the platform worker; the fixed Windows launcher also receives an absolute deadline. Cleanup/reporting has a separate maximum 5-second wait. The default total reporting budget is therefore 125 seconds, subject to the host scheduling the supervisor and allowing its small receipt write. These bounds are neither performance measurements nor changes to the frozen control fixture/protocol/RTT requirements. Inner `OperationTimeoutSec` and before/after checks only supplement the independent supervisor; they cannot preempt blocked CIM.

The worker selects the installed Codex-bundled or Program Files PowerShell 7 runtime from fixed locations. `run-packaged-job.ps1` compiles the checked-in C# helper and constructs only the fixed driver command. It accepts no caller-selected script, shell text or runtime policy. No nonce is added to its request file or process arguments. The inner driver retains the original private seven-key manifest, user/SYSTEM ACL, random nonce, canonical-path checks and inherited provider/dev/runtime opt-in refusal.

The launcher creates a new unnamed, noninheritable Job Object with kill-on-close and no breakaway allowance. `PROC_THREAD_ATTRIBUTE_JOB_LIST` associates the fixed driver helper atomically during `CreateProcess`; the helper starts suspended and resumes only after verified membership and another deadline check. This avoids the unassigned interval of creating first and assigning later. Unsupported job nesting or creation attributes fail before helper code runs. The original Codex host and existing applications are never assigned to this job. The driver and its private Electron/Node descendants inherit membership. Termination addresses only the retained job handle; there is no PID/name cleanup fallback. The supervisor worker retains its own launcher's ChildProcess handle. Closing that launcher closes its noninherited job handle if its deadline thread cannot finish.

Microsoft documents [creation-time job assignment](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-updateprocthreadattribute) and [job lifetime and descendant behavior](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects). The harness keeps these native calls confined to its Windows adapter. Fake-native tests compile the same control algorithm and never invoke that adapter.

Success requires all of the following: helper exit zero; atomic assignment and membership verification; observed zero active job processes; no timeout or forced stop; complete inner evidence; exact EXE/ASAR hashes; expected scenario/phase/PID; exact independently retained root-generation/manifest registration; zero provider effects; and the existing restart/owned-Node checks. A terminate request, process exit alone, job-handle closure or late response does not prove success. Pending native process creation and unavailable job observations report unresolved cleanup. Do not retry an unresolved cleanup or failed pilot without diagnosis and controller review.

The output directory retains `supervisor-result.json` (terminal status, accepted boolean, cleanup state, last fixed stage, duration), `job-report.json` (scalar native containment/exit/cleanup outcome), root registrations, bounded stage JSONL files and existing phase/evidence logs. The sibling `.sunny-supervisor-*` directory retains the private request and raw job report, including failed runs. Main fixture stages permit only fixed names, phase, timestamps and elapsed milliseconds; no prompts, transcripts, nonce, environment or arbitrary payloads. Root registration contains fixture process/path identity, never full command lines. None of these receipts alone attests historical crash causality, copied-profile fidelity or the large-profile responsiveness gate.
