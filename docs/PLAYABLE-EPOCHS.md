# Playable feedback epochs

The additive ordinary-run contract enrolls a committed descriptor before coordinator dispatch. `ordinary.deliverable` contains a versioned normalized descriptor and its byte hash, and `ordinary.runtimePlan` names separate startup and interaction obligations for each playable criterion. Existing `project-suite-v1` test/build entries retain their original suite-execution semantics. Runtime evidence never supplies independent semantic approval or captain acceptance.

Compatibility: MissionBook remains v3 and run version 1. Strict readers validate supported additive fields; old readers must reject unsupported fields rather than strip them or infer authority. Legacy absence remains legacy behavior. Persisted new records use the existing prewrite backup and durable publication barriers; there is no SQLite schema, storage, WAL or barrier change. Rollback must preserve the latest database, receipts and artifacts and use a compatible reader or read-only inspection, never restore an old backup over current work.

Implementation is staged under the approved Task18 design. Retained epoch histories, exact once-only feedback repair debit, finite completion effects, monotonic build/snapshot/manifest seals and private native capability require their strict cross-record validators before they can confer authority. No stored descriptor alone grants execution. Existing caps remain 16 initial assignments per graph, 32 retained assignments, 33 roots and 32 launches, cumulative across epochs.

`deliveries[].playable` stores the monotonic production, preselection-bound, artifact-sealed, selected and validation-bound stages. Before building it binds the actual producer outcome, original requested producer, guarded integration workspace, clean Git source, contribution-chain digest, enrolled descriptor/check-plan/graph digests, actual Node/npm byte identities, and distinct build/snapshot/manifest operation IDs. Each effect records its predecessor and durable receipt; snapshot inventory maps original output paths to exclusive retained asset paths. V2 manifests describe the actual `npm run build` receipt. V1 remains readable with its original node-script artifact requirement. Final validation uses separate finite check IDs and compares rebuilt mutable outputs to the retained snapshot.

Source review may finish with only exact enrolled runtime obligations missing. This enables candidate Play after every required reviewer and the validation coordinator actually finish. Runtime evidence and captain acceptance remain separate transitions. Unknown effects, stale identities, failed checks and changed bytes preserve audit records and block replacement effects.

The feedback extension retains prior epoch records and archived selected result, verification, readiness and acceptance before `MissionBook.begin` clears active fields. Each feedback operation will bind its played result and source, request digest, prior epoch, new actual attempt/task, once-only debit and completion entitlement. An entitlement waives only the repair-count stop for its exact admitted cycle and finite subjects; it cannot waive time, tokens, launches, capacity, original/current scope, controls, uncertainty or a separate conflict/finding repair charge. Prepared coordinator identities and every retained effect participate in control discovery. Recovery retains the records and gives no automatic replay authority.

Epoch storage uses `epochs` for immutable completed epoch records and `feedbackOperations` for canonical request/debit/dispatch receipts. A retained record contains the exact original epoch membership/waves plus its selected result, verification, readiness, acceptance and coordinator. The operation binds feedback/launch/result/source, the prior epoch and real newly allocated attempt/task. `completionEntitlement` is a strict staged record bound to that operation, cumulative repair ordinal and actual epoch; graph membership and fixed integration/checkpoint/production/validation operation maps are sealed before consumption. Readers cross-check historical attempts, assignment ownership and installed checkpoint waves; historical records supply audit evidence only. An unknown dispatch keeps its debit and prepared task visible and cannot be retried automatically.

Private native fixtures are four compiled branches: `journey-cue` (two complete genuine playable epochs and same-profile reopen), `journey-motion-user`, `journey-motion-system`, and `journey-audio` (fresh genuine reply journeys). Only cue permits phase 2; each manifest has exactly the existing seven keys and MiB 1. A module-private identity capability is checked before provider/store/Hub imports. The finite provider receives outbound protocol context only and uses fixed useful source edits, actual Git commits, real suite processes and independent semantic reviews. No completed mission/result/review/acceptance is seeded. The packaged supervisor retains its continuous 300-second ceiling and separate 5-second cleanup reserve, verifies raw packed entry hashes before/after and requires an exact complete four-scenario package set; source tests do not establish native feasibility.

The third-cycle entitlement includes one preallocated runtime launch, and rejects mixed worker/operation subjects, any scope outside the original grant, changed source, failed/unknown current assignments, and consumed/revoked stages. Current assignment admission failure revokes the entitlement even before delivery exists. A known closed failed preselection build retains its real failure receipt without granting snapshot/manifest effects; uncertain closure retains its reservation.

Acceptance cues use a 1.2-second animation/removal interval to leave render scheduling margin within the 1.4-second observed native limit. Actual observed disappearance is still a required native assertion. Workbench exposes the ordinary run Stop control while its room is mounted, so Stop cancels live room audio through the same shared action path.

Captain acceptance checks full quiescence before publishing its pending intent. After publication, only that consumer's exact held intent may be excluded from its read-only quiescence report, while the unchanged mission revision, actor, attempt, result and source binding are revalidated. Foreign intents, recovery records and all other effects still block acceptance; durable publication and correction ordering remain unchanged.

An owned runtime's unexpected exit is a failure even after successful startup or interaction. A failed or unknown current launch removes its runtime evidence, clears readiness and revokes the current completion entitlement. Observed normal Stop retains the successful runtime evidence. Legacy v1 manifests may include existing passed test/build IDs alongside startup/gameplay IDs only when their source and criterion bindings match; ordinary v2 runtime-plan matching remains exact.

Feedback author provider calls revalidate the exact workspace source immediately before dispatch and recheck admission after the await. Graph preparation captures immutable revision, checkpoint and retained-owner bindings and repeats source/currentness validation at the durable publication boundary. The private native fixture uses an explicitly inventoried external script and the verified manifest entrypoint under the existing preview CSP; renderer input cannot select another entrypoint. Its receipts retain actual terminal task/check/review links, preacceptance zero-onset observations and bounded late-audio observations. These are source contracts until the separate native gate observes the packaged journeys.

Correction round 1 preserves each historical ownership receipt at the initial feedback checkpoint. A later-wave author may continue that handoff only through the installed current-epoch checkpoint chain: immutable graph base, exact cumulative contribution/prefix/check proof, current ordinary transfer and every successor binding must remain valid. Historical records are not rewritten when the successor base advances. Missing historical authority or any missing/wrong current transfer still prevents scheduler reservation and dispatch.

The public manual test/build/typecheck/lint evidence action rejects ordinary supervised missions; their planned crew verification owns those finite effects. Nonexecuting inspection and legacy checks retain their existing behavior. Fresh authority is checked before the durable intent and after awaited preparation at the actual check callback. A main-held rejection may release only its exact known-unstarted intent and pending controller, after durable correction; it records no fabricated executed-check artifact. Foreign, possibly started or storage-uncertain authority remains reserved. No schema or persistence format changes are introduced by this correction.
