Back up the profile before upgrading; older releases reject these fields, so rollback requires a compatible release or preserved pre-upgrade backup, never deleting evidence.

## Review correction contract (2026-10-03)

`repairExhausted?:boolean` is optional v3 durable monotonic authority. Exhaustion follows the hard run-wide ceiling of three or a lower current grant ceiling. Once consumed, coordinator proceed/hold/reopen, pause/resume, source changes and later grant increases cannot restore repair authority. Budget admission and readiness inspect exhaustion independently of phase. Historical records without the field derive exhaustion from counters and grant; a subsequent transition preserves it.

Stable critical/important `repairFindings` block readiness across fingerprints. A closed historical status without explicit main-verifier proof is not certification. Main-only Hub.resolveRepairFinding({runId,projectId,expectedRevision,findingId,reviewId,status:resolved|dismissed,evidenceRef,source}) requires current verified workspace/integration/authorship proof and stores resolution {status,evidenceRef,source,time,actor:main-verifier}. It has no provider tool or renderer action. Task11/repair verification must explicitly invoke this trusted backend operation after genuinely verifying the change; a reviewer claiming a resolved finding or changing the source does not resolve it. The original review and ownership record remain durable.

Reviewer source validation reads actual source before and after the durable barrier, awaiting missionMutation option validation and rechecking main identities after awaits. A stale after-barrier image is corrected directly through the current authority transaction, removes readiness/verification and preserves prior historical records. No nested queued mutation runs during correction. Before-barrier mismatch invalidates through a subsequent transaction after the queue operation rejects. Failed corrective storage retains the existing uncertain-authority fence; no successful verdict response is emitted. Optional trusted correctImage callback affects only backend persistence correction and is unavailable to renderer/provider inputs.

Old v3 readability, backup/compatible rollback and fail-closed provenance requirements above still apply. These fields do not enable live supervision.
