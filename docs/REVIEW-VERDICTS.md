# Independent review contract (2026-10-03)

Workflow 1 remains historical ordered prose attribution. Workflow 2 never certifies a finished turn. Optional strict v3 run fields `verification`, `reviewCalls` and `repairFindings` retain exact source/result checks, durable provider call receipts and owner-directed findings. Old v3 records remain readable; missing evidence fails closed. Back up the profile before upgrading; older releases reject these fields, so rollback requires a compatible release or preserved pre-upgrade backup, never deleting evidence.

Main owns verification: source, selected result ID/hash, workspaceVerified and integrationVerified flags, author task IDs, durable authorSessions ({taskId,provider,threadId}) for every historical implementation session, authorshipComplete, criterion checks and artifact evidence. No renderer or provider command can install this evidence. Workspace/integration services must supply genuine verified evidence before readiness. Criteria default to test and build; documentation can explicitly justify a build not-applicable check, playable criteria require playable checks. Every check binds exact source and a nonempty evidence reference. Every required artifact binds path/hash. Downstream workspace/integration/playable services must use this contract; placeholders cannot certify readiness.

Only fresh assigned review sessions register sunny_review. Provider payload includes run/project/revision and verdict ID/source/decision/findings; reviewerTaskId, assignment and authors are derived in main. Main rejects author task or provider thread overlap, including a new task ID using an author thread. Calls bind active thread/turn/call, persist receipts before reply, deduplicate identical retries and reject changed retries across runs. Non-approval or unresolved important/critical findings prevents readiness. Repair batches increment the run-wide counter; the third blocks further repair. Stable finding IDs route to implementation path owners. Existing captain acceptance requires fresh selected content and result/hash receipt as well as current structured readiness.

Source replacement invalidates readiness and exact-source checks/reviews; historical records remain attributed. Missing or malformed evidence, failed storage, stale calls and incompatible records are rejection/recovery cases covered by isolated fixtures. Live supervision remains disabled.
