# Durable run accounting (2026-10-03)

MissionBook v3 gains optional private `accounting` on run records. It contains bounded provider/thread cumulative high-water totals, launch reservations, wall clock anchors, active and worker accrued milliseconds, uncertainty and a once-only warning marker. Old v3 runs remain readable; first admission initializes accounting without reducing existing counters. Counters, reservations and usage remain on the original run through repair, replacement sessions and grant changes.

The existing authority transaction saves accounting with dispatch identity before provider effects. Failed/uncertain storage prevents dispatch. Recovery counts elapsed wall time conservatively when quiescence was not confirmed, clamps backward time to zero and records uncertainty. Live sampling uses a process-private monotonic anchor and conservative wall elapsed time for suspend gaps. Only confirmed quiescent waiting excludes elapsed time. Runtime admission remains disabled outside trusted offline fixtures.

Budget stops use the shared run control transition and produce `stop-work` descriptions for Task 12; no separate interruption implementation is introduced. Existing backups and profile preservation apply. Rollback preserves new profiles and uses their backup for inspection rather than discarding accounting; older builds reject the added strict fields. Failure coverage includes reservation failure, receipt delay, replay, clock reversal and restart.

`desktop/run-budget.cjs` exports immutable `budgetStatus(run,{now,activeExecutions,excludeId?,reserved?})`, `reserveLaunch(run,{reservationId,assignmentId?,now})`, `observeUsage(run,{provider,threadId,totalTokens,now})`, `advanceActiveTime(run,{now,confirmedQuiescent?})`, and `globalCapacity(activeExecutions,{excludeId?})`. `now` is a nonnegative integer wall time or `{wall,monotonic?,epoch?}`; Hub supplies process-private epoch and monotonic milliseconds. `reserved` permits completion of the already counted 32nd launch; consumed usage above a lowered launch grant remains denied.

The optional accounting shape is `{usage:[{provider,threadId,totalTokens}],launchReservations:[{id,assignmentId?,time}],workers:[{id,activeMs,active}],clock:null|{wall,quiescent,uncertain,epoch?,monotonic?},warningAt:null|time,telemetryUncertain:boolean}`. Limits are 256 usage records and 32 reservations/workers, with dense arrays, unique provider/thread pairs and reservation IDs, valid assignment bindings, safe nonnegative counters, and no unknown fields. Ledger high-water sums cannot exceed consumed token counters. Lower cumulative telemetry is retained as uncertainty rather than credit. Public run summaries include only aggregate counters and `budget:{warningIssued,clockUncertain,telemetryUncertain}`; raw thread IDs, clocks and launch reservations remain private.

Worker slots include manual and island specialists, excluding read-only captain conversations and externally managed tasks. Unknown telemetry or unresolved specialist execution restricts admission to one slot. Three known active specialists exhaust capacity. Worker time is 900,000 ms, goal active time 3,600,000 ms, tokens 100,000 and launches 32, with lower approved grant values honored. The existing island scheduler samples every 15 seconds. Admission, usage, lifecycle transitions and shutdown also account immediately. Provider-confirmed human wait flags exclude active time; generic waiting does not. New provider activity ends that exclusion. A restart with unknown execution cannot assume an earlier confirmed wait persisted.
