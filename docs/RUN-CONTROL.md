# Whole-run controls — 2026-10-03

Task 12 adds optional strict fields to supervised version 1 records in MissionBook v3: controlIntent (id, action, revision, time, state pending/confirmed, optional bounded redirect), controlReport (runId, revision, queuedCancelled, interruptionRequested, confirmedStopped, unknownEffects, errors), controlAttempts (up to 32 archived objective/criteria/assignment sets), and ownedEffects (up to 256 id/runId/projectId/workspaceId/kind/state records). Reports contain bounded IDs and errors; no executable input or recovered PID is authoritative.

Old records and run:control control/objective commands remain readable. The action/redirect interface is additive; aliases cannot be mixed. IPC still requires projectId; the backend can derive it from one unique run for the documented action interface. Revision and unique project membership remain mandatory. Redirect criteria retain original criterion IDs within the original grant; objective changes do not expand activities, paths or budgets.

Intent and queued cancellation are durable before cancellation. Pause remains stopping/pending until all owned tasks, descendants, preparation, calls, checks, integration and registered effects are reconciled. Interrupt acknowledgment is only a request; reservations remain until a separate observation establishes quiescence. Resume is explicit and only admits unused queued work. Redirect archives incompatible assignments after quiescence and creates a new planning attempt with the same counters and grant; it does not dispatch.

Restart rebuilds owned-effect reservations before admission and never runs historical controls or work automatically. Unknown outcome fences survive process exit. Shutdown closes scheduler admission before receipt draining; required internal receipts remain admitted until draining completes. Failed or uncertain flush prevents a stale shutdown image write.

Saved eligible runs acquire a recovery pause intent before any scheduler can wake them. Quiet unstarted runs become confirmed paused; unresolved work stays pending without automatically issuing historical interruption. Explicit reconciliation and resume are distinct operations. Local checks and registered/integration controllers keep the active clock running while their work or outcome is unresolved, even when provider tasks have ended.

Back up the entire authority profile and managed workspaces together. No destructive migration is required. Rollback uses a release understanding these optional fields or an explicitly reconciled pre-upgrade profile; never delete unknown intents or restore over active authority. Offline failure tests cover lost provider replies, failed sibling stop, restart, stale attestation and receipt uncertainty. Runtime/provider containment gates remain false.

## Task 16 owned launch API

Before spawning, await `Hub.registerRunEffect({id,runId,projectId,kind:'launch',workspaceId?}, {exited:false,cancel,completion?})`. IDs are globally unique and bounded; workspace identity must be a retained owned workspace. Registration requires the existing live-supervision admission gate, acquires physical checkout ownership, and commits pending authority before returning the owned controller. Launch registration consumes one existing cumulative launch reservation; exhausted budgets reject without creating an effect. Call its synchronous `beforeEffect()` immediately before spawn; a changed revision, stop, pause, redirect, shutdown, exhausted budget, disabled execution gate or uncertain storage rejects. It marks runtime state running. Persisted identity takes precedence over controller fields. No caller-nominated PID becomes recovered ownership.

`cancel()` requests cancellation through the existing owned cleanup mechanism and does not certify exit. The caller records observed exit on that exact returned controller (`exited=true`, `state='completed'` only when outcome and cleanup are known) and awaits `Hub.settleRunEffect({runId,id}, controller)` to durably release the reservation. Unknown outcome requires reconciliation and cannot be settled by exit alone. Recovered controllers have no cancel handle, PID or exit proof. An optional `completion` promise covers the entire owned operation including its required final receipt; shutdown drains it before closing authority admission. Main-owned integration, combined checks and mission checks use the same dispatcher and are tracked through their receipt completion.

The additive resumePhase field preserves review-only admission across pause/resume. Redirect archives old assignments and criteria; old task, review, workspace and budget identities remain in the run, and a subsequent explicit new plan appends distinct assignment IDs within the existing 32-assignment/launch limits. New criterion wording retains original check/artifact requirements and original criterion IDs. Reports and intent status are sanitized through the existing state projection; action-form IPC returns run/report while legacy control-form IPC keeps its existing run-summary response.
