## Decision and scope

Captain requested the crew hierarchy and expandable profiles first, followed by the ship log, Captain's Orders, parchment and ocean treatment. Implemented on `codex/crew-map`, based on merged studio `c6aa0ca`, in `.sunny-dev/crew-map`. The earlier Projects checkout and installed application are separate.

Luffy has a distinct navy captain panel. Nine core specialists share equal grid tracks and wanted-poster cards; optional island specialists retain the same card treatment in their existing disclosure. Existing portraits and all atlas/room geometry are unchanged. The native profile dialog keeps Escape, focus containment, focus return and unsaved-note protection, adding assignment previews, local council contributions and direct room/evidence navigation. Active conversations sort before recent inactive ones.

The crew map uses original SVG paths measured from the rendered captain and cards. A finite outbound pulse follows a newly observed explicit Luffy child task or saved local-council assignment; an inbound pulse follows a finished task with a saved reply or a ready council contribution. Mounting, duplicate snapshots, changed epochs, stale timestamps, uncertain persistence and metadata-only finished-task refreshes cannot trigger a pulse. Pause, page hiding, offscreen map and OS/Sunny reduced motion suppress effects. Suppressed events are not replayed on resume. Decorative lines show coordination hierarchy, not runtime dependencies or completion.

The ship log lists persisted mission events and captain decisions, explicit delegation records, saved Zoro council reviews and latest conversation states. It does not claim to be a complete event journal: task summaries retain latest state, and councils have no per-contribution timestamps. Council rows explicitly say **Council last updated**. Details expose the saved record/output; task-backed entries open the exact conversation. Project filtering and Show more keep older records accessible. Scrolling never measures completion.

Captain's Orders extends the existing Ctrl/Cmd+K native command menu with crew rooms and pending approval inspection. All actions navigate through existing guards; opening a request cannot approve it or start a mission. Projects, conversations, stable selection, IME handling and keyboard routing are preserved.

Original low-contrast CSS fibers texture cards, logs, the captain objective and Zoro ledger. A small CSS sea porthole lives away from controls, sharing the map's visual pause/visibility/motion policy. No WebGL renderer, additional package, database schema, provider capability or privileged IPC action was added.

## Modern React component audit — second pass, 2026-11-07

Research decision record: [modern component research](crew-components-research-2026-11-07.md). No new dependency or privileged API is needed. Original implementations borrow interaction principles, not third-party source.

| Before | After | Why |
| --- | --- | --- |
| Two copies of Ship's log | One searchable log, project and record filters | Avoid duplicate evidence and duplicate accessible IDs |
| Profiles open setup | Overview opens assignments, output and room; separate setup remains mounted | Put the work first; preserve setup drafts when changing sections |
| Mission names absent from command search | Actual missions navigate to their saved active attempt; result category labels | Find existing work without starting or approving it |
| Large captain/cards and crossing lower connectors | Tighter equal cards, real projected status, gutter-routed lower branches | Expose hierarchy and distinguish idle, waiting and review states |
| 44px porthole observing entire map | Larger decorative window with its own intersection observer | Stop ocean motion when the window itself is offscreen |
| Repeating CSS fibers | Original low-opacity static SVG grain on parchment surfaces | Richer material without a WebGL runtime or moving text background |
| Dialog animates for every opener | Brief pointer-only entrance; keyboard and reduced motion open still | Preserve orientation and responsiveness |

The log now projects saved check artifacts and captain review decisions, preserving exact attempt IDs for evidence navigation. Local council timestamps remain labelled as last-update times. Card status reuses the existing authoritative crew projection. No acceptance is inferred from replies or check success. Profile output is a saved preview; the evidence button opens the source conversation.

The ocean remains an original CSS approximation, not the Paper WebGL shader. Profiles retain Sunny's native modal rather than a shared-layout morph. These are intentional lightweight adaptations of the requested six experiences.
